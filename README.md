# Focus Point

نظام إدارة **مساحة دراسة راقية** (طاولات دراسة + مراسم فنّية) مبني على **Next.js** (App Router) و **Prisma ORM** و **PostgreSQL محلي**.

- نسخة الطالب: تسجيل دخول سريع عبر الباركود، تخصيص كرسي حر، جلسة حيّة، وطلب خدمات (مشروبات/طباعة).
- نسخة صاحب المكان (الأدمن): نظرة عامة حيّة بالإيرادات والإشغال، خريطة الأماكن، إدارة الجلسات النشطة، الطلبات الواردة، إدارة الخدمات، **والتقارير اليومية مع تصدير Excel منسّق**.

> **القرارات التقنية الجوهرية:**
> - PostgreSQL **مثبّت محلياً مباشرةً على الجهاز** — بلا Docker، بلا Supabase، بلا أي خدمة سحابية.
> - بديل الـ Realtime (Supabase) هو **تساؤل دوري (polling)** من الواجهة كل بضع ثوانٍ.
> - الأزمنة تُخزَّن **بالتوقيت المطلق (UTC)**، وأي حساب "لهذا اليوم" (إيرادات اليوم، التقارير) يُجرى بمنطقة **دمشق (Asia/Damascus)**.

## 2) تثبيت PostgreSQL محلياً (Linux / macOS / Windows)

| نظام | الخطوات |
|---|---|
| **Windows** | نزّل المثبّت من [postgresql.org](https://www.postgresql.org/download/)، شغّله وحدّد كلمة سر لمستخدم `postgres`. بعد التثبيت تأكد أن خدمة `postgresql-x64-18` تعمل (ابدأ → `services.msc`)، وpsql تجده في `C:\Program Files\PostgreSQL\18\bin\psql.exe`. |

## 3) الإعداد المحلي خطوة بخطوة

### 3.1 تثبيت الاعتماديات

```bash
npm install
```

```bash
psql -U postgres -h localhost -p 5432 -c "CREATE DATABASE focus_point;"
```

### 3.3 تعبئة ملف البيئة `.env.local`

انسخ `.env.local.example` إلى `.env.local` وعدّل القيم (التفاصيل في القسم 4). أسهل نسخة تعمل محلياً:

```
ADMIN_PASSWORD=WhateverYouWant
```

> `.env.local` **لا يُرفع إلى git** (مستثنى في `.gitignore`)، وملف `.env.local.example` هو المرجع الموثّق للمتغيرات.

### 3.4 تشغيل الـ migrations وتوليد عميل Prisma

```bash
npm run db:migrate     # prisma migrate dev — ينشئ/يطبّق migrations على focus_point
npm run db:generate    # prisma generate — يولّد Prisma Client في prisma/generated/prisma
```

- الـ migrations تشمل: الجداول الخمسة + CHECK constraints (أسماء القاعات و`seat_group`) + دالة `assign_random_chair`.
- **Prisma 7** لا يولّد العميل تلقائياً بعد `migrate` — شغّل `db:generate` يدوياً عند الحاجة.

### 3.5 البيانات الأولية (اختياري)

```bash
npm run db:seed        # prisma db seed — 35 كرسياً + 5 خدمات
```

- **35 كرسياً** موزعة على 4 مجموعات:
  - `social_table` → كل كراسي Social (15)
  - `silent_writing` → طاولتا الكتابة الكبيرتان في Silent (8)
  - `silent_bar` → البار الدراسي في Silent (6)

- **5 خدمات**: طباعة أبيض وأسود (500 ل.س)، طباعة ملونة (1500)، شاي (1500)، قهوة (2500)، عصير (3000).

> Prisma 7 لا يشغّل الـ seed تلقائياً بعد migrations — يشغّله يدوياً عند الحاجة.

### 3.6 تشغيل خادم التطوير


## 5) نموذج البيانات

خمسة جداول في قاعدة `focus_point`:

| الجدول | الأعمدة | الوصف |
|---|---|---|
| `students` | `id` uuid, `name`, `phone?`, `created_at` | الطلاب؛ يُعاد استخدام سجل الطالب نفسه عند عودته (نفس الاسم/الهاتف) |
| `spots` | `id` uuid, `room`, `group_label`, `seat_number`, `seat_group` | كل صف = **كرسي فعلي واحد**. `room`: social / silent / smoking (CHECK) |
| `sessions` | `id`, `student_id`, `spot_id`, `check_in`, `check_out?`, `status` | الجلسة = شغل كرسي. `status`: active / ended. الفهرس الفريد الجزئي يمنع أكثر من جلسة نشطة لنفس الطالب |
| `services` | `id`, `name`, `category?`, `price` (Decimal) | الخدمات المعروضة (طباعة / مشروبات) |
| `orders` | `id`, `session_id`, `service_id`, `status`, `details` (jsonb), `created_at` | طلب داخل جلسة. `status`: pending / done / cancelled (CHECK) |

**تخصيص الكرسي:** دالة SQL `assign_random_spot`/`assign_random_chair(p_seat_group, p_student_id)` تختار كرسياً حراً عشوائياً ضمن مجموعة الكراسي المطلوبة مع حماية التزامن (قفل `FOR UPDATE SKIP LOCKED`) وتُنشئ الجلسة في نفس العملية، عبر `$queryRaw` في `src/app/api/assign-chair/route.ts`. هذا يمنع تخصيص نفس الكرسي لطالبين حتى مع طلبات متزامنة.

### بنية `orders.details` (jsonb)

حقل تفاصيل مرن حسب نوع الطلب:

- **مشروبات:** `quantity` (كمية)، `sugar` (لشاي/قهوة فقط: بدون سكر / سكر خفيف / سكر متوسط / سكر زيادة)، `note` (ملاحظة اختيارية). **عصير لا يقبل حقلاً للسكر أبداً.**
- **طباعة:** `file_name`, `file_path` (الاسم المخزن `uuid.الامتداد`), `file_type`, `file_size`, `print_type` (`black_white`/`color`), `copies` (1..4), `paper` (a4/booklet), `print_mode` (وجه واحد/وجهين), `orientation` (عمودي/أفقي), `note`.

تميّز الأنواع الثلاثة من التعبئة عبر المفتاح `print_type` (راجع `src/lib/orders.ts`).

## 7) تدفق الطالب بالتفصيل

### 7.1 التسجيل وتخصيص الكرسي

1. `/checkin` → `POST /api/checkin` يُنشئ الطالب (أو يعيد سجلّه السابق) ويُرجع `student_id`.
2. `/checkin/room` → الطالب يختار قاعة:
   - **Social / Smoking**: تخصيص مباشر.
   - **Silent**: سؤال الهدف → `silent_writing` (طاولات الكتابة) أو `silent_bar` (البار الدراسي).
3. `POST /api/assign-chair` `{ student_id, seat_group }`:
   - يرجع `session_id` + الكرسي المُخصَّص (`group_label` + `seat_number` + `room`).
   - إن كانت للطالب جلسة نشطة أصلاً: يُوجَّه إليها بدل الإنشاء.
   - إن لم يوجد كرسي حر: رسالة "لا توجد كراسي متاحة" (مع `no_spot`) — ولا يُعتبر خطأ خادم.
   - سباق متزامن نادر (فهرس فريد) يُعالج بإعادة التوجيه للجلسة النشطة بدل فشل.

### 7.2 صفحة الجلسة الحيّة (`/session/[id]`)

- تعرض اسم القاعة/المكان مع **عداد مدّة حيّ** يُحدّث كل ثانية، مبني على فرق `now − check_in` المُقاس على الخادم لحظة التحميل.
- **إنهاء الجلسة حصراً من الأدمن**: الطالب **لا يملك زر إنهاء**؛ النص التوضيحي في صفحة الجلسة يوجّهه "لإنهاء جلستك، راجع فريق المركز". بعد الإنهاء يُوجَّه الطالب تلقائياً لصفحة الانتهاء.
- **مراقبة الانتهاء:** تساؤل دوري لـ `/api/session/[id]/status` كل 5 ثوانٍ (بديل Realtime). عند `ended` → توجيه فوري لـ `/session/[id]/ended`. عند `404` (جلسة غير موجودة) → يُعالج ضمنياً.
- فحص server-side عند التحميل: جلسة منتهية → توجيه مباشر؛ جلسة غير موجودة → `404`.
- `ActiveSessionGuard` يخزّن `session_id` النشط محلياً فيصل الطالب إلى جلسته مباشرة حتى لو أعاد فتح المتصفح.

### 7.3 طلب الخدمات (`/session/[id]/services`)

- القائمة تُقرأ من جدول `services` **مجمّعة حسب `category`** (طباعة / مشروبات) لطلاب الجلسة النشطة فقط.
- **مشروب:** اختيار مستوى سكر (شاي/قهوة) + كمية اختيارية + ملاحظة.
- **طباعة:** اختيار النوع (أبيض وأسود/ملوّن)، رفع ملف، و**عدد النسخ من 1 إلى 4 كحد أقصى** (تُتحقق الواجهة والخادم معاً — رفض "عدد النسخ يجب أن يكون بين 1 و 4").
- قواعد رفع الملف: **الحد الأقصى 20MB**، الامتدادات المسموحة: `PDF, JPG, PNG, DOC, DOCX, XLS, XLSX, PPT, PPTX`. السعر ثابت لكل خدمة (أبيض وأسود 500 / ملوّن 1500) عبر ربط الطلب بخدمة طباعة حسب النوع.
- `POST /api/orders` يُنشئ الطلب بـ `status='pending'` بعد تحقق يدوي: الجلسة موجودة؟ نشطة؟ (منتهية → `409`)، الخدمة موجودة؟ details صالحة؟ والكمية/السكر مسموحان؟
- بعد الإرسال: رسالة "تم إرسال طلبك" مع اختيار طلب آخر أو العودة للجلسة.

## 8) لوحة الأدمن بالتفصيل

### 8.1 الدخول والجلسة

- `POST /api/admin/login` بقيمة `ADMIN_PASSWORD` (من `.env.local`) → كوكي جلسة `fp_admin_session` (httpOnly, SameSite=Lax, صلاحية 12 ساعة).
- الكوكي **مشتق hash** من كلمة المرور (SHA-256) فلا يمكن تزويره دون معرفتها، والمقارنة عبر `timingSafeEqual`.
- الحماية على الصفحات: `requireAdminOrRedirect` (إعادة توجيه لـ `/admin/login`)؛ وعلى واجهات الـ API: `requireAdminJson` (401).
- تسجيل الخروج: زر من الشريط الجانبي/العلوي (يُحذف الكوكي).

### 8.2 الأقسام

- **نظرة عامة (`/admin`)**: بطاقة "إيرادات اليوم" (مجموع الطلبات `done` لليوم بمنطقة دمشق) + بطاقة "الإشغال الحي" (كراسي مشغولة من أصل 35، حسب القاعة). التساؤل الدوري كل 5 ثوانٍ.
- **الأماكن (`/admin/spaces`)**: خريطة لجميع الكراسي، مشغول/فارغ، مع مدة الجلوس الحيّة في الـ tooltip (كل 5 ثوانٍ).
- **الجلسات النشطة (`/admin/sessions`)**: جدول الجلسات النشطة مع زمن الدخول والمدة، وزر **"إنهاء الجلسة"** (الطريقة الوحيدة لإنهاء جلسة).
  - إنهاء الجلسة (`POST /api/admin/end-session`) **يلغي تلقائياً كل طلباتها المعلّقة** (`pending → cancelled`) ويسجّل `check_out` ويفرّغ الكرسي.
- **الطلبات الواردة (`/admin/orders`)**: قائمة الطلبات المعلّقة (كل 3 ثوانٍ، الأكثر حساسية)، مع:
  - عرض مكان الطالب (القاعة • المقعد).
  - **عرض/تحميل ملف الطباعة** عبر `/api/admin/files/[name]` (محمي بجلسة الأدمن — لا يُكشف المسار الثابت).
  - زر **"تم"**: `POST /api/admin/orders` `{ order_id }` يحوّلان حالة الطلب إلى `done` (Idempotent — طلب منتهٍ يُعاد بنجاح صامت).
- **الخدمات (`/admin/services`)**: إضافة/تعديل/حذف خدمة (الاسم، التصنيف، السعر).
- **باركود الاستقبال (`/admin/qr-code`)**: يولّد QR لعنوان `/checkin`، مع كشف تلقائي لعنوان IP الحقيقي للجهاز على الشبكة المحلية عبر `/api/server-info` (يتجاهل المحولات الافتراضية Hyper-V/VMware/…)، ويمكن ضبط العنوان يدوياً عبر `NEXT_PUBLIC_CHECKIN_URL`.

### 8.3 فترات التساؤل الدوري

| القسم | الفترة | المرجع |
|---|---|---|
| نظرة عامة / الأماكن / الجلسات | 5 ثوانٍ | `src/lib/admin-poll.ts` |
| الطلبات الواردة | 3 ثوانٍ | `POLL_ORDERS_MS` |

## 9) التقارير اليومية وتصدير Excel (ميزة حديثة)

صفحة **"التقارير"** في لوحة الأدمن (`/admin/report`) تعرض سجل الخدمات المقدمة **لكل طالب على حدة**، وتولّد نسخة من قاعدة البيانات يومياً حسب الفترة.

### 9.1 الواجهة (`/admin/report`)

- حقل **من تاريخ / إلى تاريخ** (افتراضياً اليوم) — تُحسب الأيام وفق **توقيت دمشق**.
- بطاقات الإجماليات: طلاب زارونا، إجمالي الطلبات (تم/معلّق/ملغى)، إيرادات الفترة (مجموع الطلبات `done` فقط)، عدد الخدمات المباعة.
- جدول **ملخص الخدمات**: كل خدمة → عدد الطلبات / المكتملة / الإيرادات.
- **سجل كل طالب**: قسم مستقل لكل طالب فيه جلساته وطلباته وتفاصيل كل طلب (الوقت، المكان، الخدمة، التفاصيل مثل "كمية: 2 • سكر: سكر متوسط" أو خيارات الطباعة + اسم الملف، السعر، الحالة).

### 9.2 تصدير Excel (`GET /api/admin/report?from=...&to=...&format=xlsx`)

- زر "تنزيل Excel منسّق" يفتح نفس عنوان الـ API مع `format=xlsx`.
- يُبنى عبر مكتبة **exceljs** بألوان الهوية (خلفيات عنابية للعناوين، تظليل متناوب، أرقام مالية منسقة، اتجاه يمين-لليمين).
- **أربع أوراق:**
  1. **ملخص اليوم** — الإجماليات + جدول الخدمات والإيرادات المرجعية.
  2. **سجل الطلاب** — لكل طالب: الجلسات، الطلبات، إجمالي المُنفّذ (ل.س).
  3. **تفاصيل الطلبات** — كل طلب: الوقت، الطالب، المكان، الخدمة، التفاصيل، السعر، الحالة.
  4. **الجلسات** — الدخول/الخروج، المدة (ساعة:دقيقة)، الحالة.

> **الطبيعة:** تقرير **لقطة للقراءة فقط** (SELECT) من قاعدة البيانات المحلية ضمن الفترة المحددة — **ملف Excel هو نسخة من قاعدة البيانات، والبيانات تبقى محفوظة كما هي في القاعدة الأصلية**. الإيرادات تحسب من الطلبات `done` فقط (المعلّق/الملغى لا يُحسب). منطق التقرير في `src/lib/report.ts` والواجهة في `src/app/api/admin/report/route.ts`.

## 10) دورة حياة الطلب

```
طلب طالب   → pending   → (الأدمن: زر "تم")  → done   [يُحتسب في الإيرادات اليومية/التقارير]
                        → (إنهاء الجلسة)     → cancelled [لا يُحتسب]
```

- `done`: يُتمّه الأدمن يدوياً (Idempotent).
- `cancelled`: يُعيّن **تلقائياً عند إنهاء الجلسة** لكل طلبها الباقي معلّقاً.
- لا إلغاء يدوي من الطالب؛ الطالب يستطيع ترك الطلب معلّقاً فقط حتى ينتهي دوره أو تنتهي الجلسة.

## 12) الأمان

> **لا توجد طبقة حماية على مستوى قاعدة البيانات** — لا RLS ولا policies (Postgres محلي مباشر). لذلك كل تحقق يُنفَّذ **يدوياً داخل route handlers** (مرجع: تعليقات `src/lib/prisma.ts`):

- قبل أي عملية حساسة: تحقق من وجود الجلسة **ونشاطها** وصاحبها ومن أين جاء الطلب.
- لوحة الأدمن محمية بكوكي جلسة httpOnly مشتق من كلمة المرور (hash) مع مقارنة آمنة؛ صفحات الـ API محمية بـ `requireAdminJson`.
- **رفع الملفات:** حفظ باسم `uuid.الامتداد` داخل مجلد `UPLOAD_DIR`، والخدمة عبر مسار محمي (`/api/admin/files/[name]`) بفحص صارم ضد `path traversal` (يرفض أي اسم يحوي مكونات مسار)، والامتداد + الحجم (20MB) يُتحققان قبل الكتابة.
- **التعامل مع أخطاء القاعدة:** `src/lib/api-error.ts` يوحّد رسائل عربية لطيفة ويمنع تسريب أخطاء DB الخام إلى العميل؛ انقطاع الاتصال يُترجم لـ "تعذّر الاتصال بقاعدة البيانات، الرجاء المحاولة مرة أخرى" وتتعافى الواجهات تلقائياً عند عودة الخدمة.

## 16) استكشاف الأخطاء

### Prisma 7 — تغييرات عن الإصدارات السابقة

- عميل جديد `prisma-client` (بلا Rust) يتطلب **driver adapter** (`@prisma/adapter-pg`) يُنشأ في `src/lib/prisma.ts`.
- `output` مطلوب في الـ generator → العميل يُولَّد في `prisma/generated/prisma` (مستثنى من git).
- متغيرات البيئة لا تُحمَّل افتراضياً → `prisma.config.ts` يقرأ `.env.local` عبر dotenv.
- `migrate dev` و `db push` لا يعملان generate/seed تلقائياً.

### المنطقة الزمنية

- يفرض اتصال pg على `timezone=UTC` صراحة ليبقى التخزين بالتوقيت المطلق. عولجت هذه النقطة بعمق في `src/lib/prisma.ts` — لا تعدّلها إلا بفهم كامل للأثر على "إيرادات اليوم" والتقارير.

### لماذا `--webpack` في سكربتات npm؟

في بعض بيئات Windows ملف `@next/swc-win32-x64-msvc` لا يُحمَّل (خطأ "not a valid Win32 application")، فيرجع Next لـ WASM. **الرسالة غير ضارة**، والوضع المدعوم يعمل عبر webpack — لذا البناء يستخدم `next build --webpack`.

### مشاكل شائعة

- **صفحة/مسارات لا تتحدث بعد تعديل**: خادم `next start` يخدم بناء قديم — أعد `npm run build` ثم أعد التشغيل.
- **/api/health تولد "تعذّر الاتصال بقاعدة البيانات"**: خدمة PostgreSQL متوقفة — أعد تشغيلها (`services.msc` على Windows)، والنظام يتعافى تلقائياً دون إعادة تشغيل Next.
- **لا يوجد منفذ 3000 مزعوم**: قد يكون منفذاً آخر مستعملاً — غيّر `PORT` أو أوقف العملية التي تستخدمه.
- **تحذير `outputFileTracingRoot` / تجاهل package-lock**: تحذير غير ضار في بيئة Windows — يُظهره Next عند وضع المشروع تحت مسار عميق مثل `C:\Users\...\Desktop\...`.

## 18) ملاحظات تشغيل يومية (سريعة)

1. **صباح كل يوم** → الأدمن: افتح "التقارير" واختر الفترة المطلوبة (غالباً الأمس).

4. **إنهاء جلوس** الطالب عند خروجه من قسم "الجلسات النشطة" — تُلغى معلّقاته ويفرغ كرسيه.
